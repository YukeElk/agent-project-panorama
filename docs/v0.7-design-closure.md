# V0.7 Guided Visual Explanation 设计闭合

状态：**WP0–WP6 Closed；Machine Gates Passed；Exact Artifact Human Acceptance Pending**

日期：2026-08-22

对应 Finding：SF-57

维护修订：SF-58、SF-59（统一正式 Renderer、详细节点/Risk/Decision Story、动态重编译与交互状态清理）

## 1. 闭合结论

V0.7 保持单一 Skill 和 Codex 运行终端。它不复制或硬依赖 Visualize 插件源码，而是实现一份证据绑定的
Explain Pack，并由 Codex 对话内 Fragment 与 Panorama Dialog 共同消费：

```text
Panorama Core + Model/View IR + Guided View Set
                         ↓ deterministic, read-only
                 Panorama Explain Pack
                    ↙                 ↘
       Codex Visualize Fragment   Panorama Dialog
```

Explain Pack 是第五层阅读投影，不改变 V0.6 四层事实/模型/视图/布局边界。Decision 等治理实体通过 exact
Core Reference 进入讲解，不扩展 Model IR v0.1 的 Entity/Relation Enum。

## 2. 发布范围

V0.7.0 必须同时完成：

1. 六类现有 View Profile 的逐步讲解；
2. Decision 与 Risk Story；
3. Transition、Evidence/Freshness、Verification Trace 三类跨图 Story；
4. Codex 对话内无网络 Fragment 与 Markdown/Mermaid 降级；
5. Multi-view Renderer 的同源 Dialog、图形聚焦和键盘路径；
6. Explain Pack/Bundle/Verified Delivery 的 Hash Binding；
7. Controlled、PetClinic、Backstage、治理型和 Event 型至少五个 Case 的机器验证；
8. 精确代表 Artifact Hash 的独立人工视觉 Acceptance。

任何只完成五类图、只完成对话表面、只完成 Panorama Dialog、或只生成自由文本的实现都不满足发布范围。

维护闭合进一步要求：Guided Viewer 只能作为正式 Renderer 的讲解模式，不能替代三主视图、Evidence Inspector 或
Studio；每个 View 必须包含整图和逐节点细节，Risk/Decision 必须回答成因/必要性、影响、措施与可能结果；讲解随
Core/Event/Model/View Hash 变化确定性重编译，旧包失败关闭。

## 3. 固定边界

- 不新增主导航、云端后端、React/Vue、通用 Agent 平台或业务项目写入；
- 不从截图、DOM、布局或模型自由文本制造事实；
- 不把静态 Dependency 提升为 Runtime Call/Sequence；
- 不把 Risk Emphasis 变成 Formal Finding 或 blast radius；
- 不修改 Decision/Review/Gate/Acceptance；
- Viewer State 不进入 Semantic Hash；
- Visualize 能力不可用时 Skill 仍然可用；
- Fragment 只写入 Codex 任务专属可视化目录，不进入发布包或目标项目。

## 4. 门禁

Explain 编译、验证、Fragment、Dialog Candidate 和 Browser QA 是 Read-only/Automatic Quality。last-good 晋升沿用
`verified_delivery.promote`；公开 Tag/Release 与精确代表制品的人工接受仍属于 Decision Gate。失败的机器门禁
不能通过增加人工点击绕过。
