# V0.1.1 Control & Safety Hardening Plan

基线提交：`708f70ef94bee2fa84a55a6601e6fbb58abe08e3`

本轮保持 V0.1 产品定位、Single HTML Renderer、三个一级视图和冻结的
`panorama.schema.v0.1.json`。普通项目数据更新仍只允许替换
`project-panorama-data` payload；Renderer、DOM、CSS、JavaScript 和未知扩展字段必须保留。

## 执行顺序

1. 先用失败测试固定 Approval Hash、历史 Next Focus、Secret 脱敏、Git 风险、URL 安全、
   Gate/Review 规则、结构化 Findings、多 Deployment、Resource Pool、Inspector、INIT、
   Proposal 和连续生命周期的预期。
2. 依照整改指令顺序实现 P0-01 至 P0-11。
3. 在不修改 v0.1 Schema 的条件下完成 P1-01 至 P1-07；需要持久化新语义的部分使用
   `extensions` 作为明确的 V0.1.1 兼容层。
4. 重新生成 Reference HTML，运行 Python、Validator、Renderer、Presentation Hash、浏览器
   和连续三次 Update 生命周期检查。
5. 更新 README、SKILL 与验收报告后停止，不执行 V0.2 Migration。

## Schema 边界

- V0.1.1 不修改 `schema/panorama.schema.v0.1.json`。
- Approval 元数据属于 Update Package，不进入 Panorama Data Schema。
- 当前 Guidance 与历史 Next Focus 的兼容记录放入现有 `extensions`；V0.2 再建立正式
  UpdateBatch Guidance Snapshot。
- Validator Finding 的严重度和结构化输出属于工具报告模型，不改变 Panorama Schema。
- Template/Renderer/Skill compatibility 先以常量和运行时检查实现，不覆盖 v0.1 Schema。

## 停止条件

V0.1.1 必须通过自动测试和 UI 检查，并输出独立验收报告。V0.2 仅记录 Migration Proposal，
不创建 v0.2 Schema、不执行迁移。
