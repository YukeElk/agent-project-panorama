# V0.8.0 Release Audit

日期：2026-08-23

状态：**Post-acceptance Correction Implemented / New Browser Evidence & Human Visual Acceptance Pending / 发布阻断**

候选分支：`agent/v0.8-unified-canvas-flow`

Git 基线：`6483840fd0a05e9f357a5e4bc5e0d5cdf2a72f12`（`v0.7.0`）；当前候选仍是未提交工作树，PVD 只绑定精确制品字节，
不冒充最终 Release Commit。

## 1. 审核结论

V0.8 父子语义画布曾关闭上一候选的机器门禁，并取得对精确 PVD 与 Artifact SHA-256 的独立人工视觉接受；
验收后用户报告三个编辑模式缺陷，因此该接受只保留历史效力，当前发布重新阻断。修复候选已经生成并通过源码与
自动化回归，但尚未取得绑定新字节的浏览器证据、Verified Delivery 和独立人工视觉接受。机器 Receipt 的
`visualReview` 按合同仍为 `pending`，last-good 未修改；尚未创建最终 Commit、Tag 或 GitHub Release。

本次发布审核发现并修复了两个真实候选阻断项：

1. Verified Delivery 原先未把 `child_views` 传给 Bundle，可能生成丢失模块内部逻辑的 PVD；现在 CLI 显式接受
   `--child-view`，Bundle Hash 传递绑定子 View，Geometry 同时验证父/子 View，并新增回归测试。
2. 六视图候选的部署图存在 3 条渲染后连线穿节点，窄屏 Fit 也会裁切节点；现在部署视图使用
   “输入/上游 → 核心/汇聚 → 输出/下游”三列语义布局，360px 起的相机 Fit 可完整容纳场景。

## 5. 历史 Agent 只读视觉巡检

应用内浏览器已逐项检查：

- 六类顶层 View 在同一 Canvas Runtime 中切换，中文主名称与技术名/ID 同时保留；
- 单击编排器立即显示“设计需求 → 设计原因 → 实现功能 → 系统角色 → 交互方式 → 技术选型 → 风险”；
- 双击进入编排器内部逻辑，外部项目控制台保持紧凑引用，不展开其内部逻辑；
- 风险 Story 第 4 步明确展示应对措施；
- 六步业务流可启动并显示当前步骤、数据和结果，节点随播放聚焦；
- 编辑模式继续使用同一画布，显示隔离 Target Candidate；离线治理按钮保持禁用；
- 修复后的部署视图显示“上游—部署核心—资源/发布”结构，机器路径采样为 0 穿节点。

该结论是 Advisory Review，不能写入机器 Receipt 的 `visualReview` 字段。
