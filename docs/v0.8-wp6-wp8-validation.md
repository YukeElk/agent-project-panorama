状态：历史实现与机器验证通过；原 PVD 接受已被验收后缺陷报告替代；修复候选重新验证中；Commit/Tag/Release/last-good 尚未执行

## 验证结论

V0.8 父子语义画布已经满足本轮批准范围：查看与讲解合并为阅读模式，Studio 迁入同一 Canvas Runtime 的编辑模式；
架构主画布与模块内部逻辑子画布共享相机、选择和导航；讲解、节点、进度、风险/决策与业务流程演示是同一场景的
Knowledge Lens，不再拥有第二套图形。

中文 `displayName` 是 Layer、Module 与 Logic Node 的主扫描标签，技术名、稳定 ID 和事实状态保留为副标签。
旧数据缺少中文名时兼容显示技术名并产生 Information Gap，Renderer 不自动翻译或写回。

## 功能闭环

- 节点单击立即显示完整逻辑链：设计需求、设计原因、实现功能、系统角色、内部处理、外部交互、技术选型与 Evidence/Gap。
- 主画布双击 Module 进入模块子画布；子画布只展开当前模块，其他模块/资源保持紧凑外部引用。
- 风险 Story 覆盖成因、触发、影响/可能结果、应对措施、剩余风险与跟踪；决策 Story 覆盖为什么现在决策、候选项、
  收益/代价、影响范围、推荐/已选结果和未决条件。
- WorkItem 进度与 Layer/Module/Logic Node 精确绑定，并分离实现、验证、批准和部署语义。
- Business Flow 只沿正式 Module/Connection Path 播放，支持播放、暂停、重播、速度、Reduced Motion 和打印静态化。
- 编辑模式只修改隔离 Target Candidate；Layer/Module/Connection 与 Module Logic Node/Edge/Port 可编排，
  Current Observation 保持只读；正式化仍按 Session CAS → Validate → Review → Proposal → Exact Approval → Apply。

## 真实项目验证

### AI Wiki

使用现有完整 Panorama Core 重新编译统一画布：7 个 Layer、21 个 Model Entity、14 个 Relation、2 个顶层
Architecture View 和 38 个 Explain Story。阅读/编辑使用同一画布，Studio 可从 Current 创建隔离 Target Candidate；
离线环境下治理动作保持禁用，不绕过 Studio Bridge。

AI Wiki 是旧 Core，未 authored 中文 `displayName`；本轮按兼容合同保留技术名并记录 Gap，没有运行时翻译或污染 Core。

### Spring PetClinic

对真实固定源码切片重新抽取：53 个受支持文件、255 个 Source Element、498 个静态 Relation。Owner 领域模块清单
精确包含 12 个 Java 文件、33,980 bytes，无范围截断。Java 适配器是 bounded partial parser，因此 Observation/Child
Binding 保持 `partial/recorded_as_of`，并披露：

- `java_full_parser_not_used`；
- `java_reflection_generated_sources_and_calls_not_resolved`；
- `static_dependencies_do_not_prove_runtime_calls_or_sequence_order`；
- `module_scope_contains_partial_or_failed_parse`。

生成的子画布只把带文件 digest 和 Source Location 的静态事实标为 `derived/inferred`，不宣称 Spring 注解、反射或
静态 import 已证明运行调用。

### Backstage TypeScript Slice

对真实固定源码切片重新抽取：295 个受支持文件、349 个 Source Element、710 个静态 Relation。Catalog Client
模块清单精确包含 65 个 TypeScript 文件、256,806 bytes，无范围截断。Observation/Child Binding 保持
`partial/recorded_as_of`，并披露：

- `javascript_typescript_full_parser_not_used`；
- `dynamic_or_unresolved_dependencies_present`；
- `static_dependencies_do_not_prove_runtime_calls_or_sequence_order`；
- `module_scope_contains_partial_or_failed_parse`。

多项目验证发现并修复了一个真实冲突：旧 Model 编译器拒绝所有 partial Observation，导致诚实披露缺口的 Java/TS
项目无法进入子画布。现在仅允许已校验的 `current|recorded_as_of`、`complete|partial` Observation；
`stale|unknown` 继续失败关闭，Binding 和 View 强制暴露 Coverage/Currentness/Gap。

## 对抗与治理验证

对抗夹具覆盖 preprocess、LLM call、Loop/退出、Tool call、Retry、Fallback、State Read/Write、动态调用和生成代码
缺口。Loop 无退出条件或无 `loop_back`、未知端点、Evidence 越界、Source Hash 漂移、外部引用泄漏其他模块内部逻辑、
未绑定边界端口、Candidate/Formal 身份错配均失败关闭。

Current 不可编辑、Target Candidate 隔离、Source Drift 使校验/提案 stale、Semantic/Layout Hash 分离、
Proposal/Approval/Apply 精确 Hash 治理均通过既有与新增测试。
