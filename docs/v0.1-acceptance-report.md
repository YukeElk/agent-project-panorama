## 5. Patch Apply 安全契约

- 仅支持 `add / replace / remove` JSON Patch 子集和 JSON Pointer。
- Apply 前验证 Base Revision 与 Base Data Hash。
- 使用同目录独占锁串行化协作写入，并在提交前重新比较目标字节，拒绝 TOCTOU 覆盖。
- 修改前创建同目录时间戳备份。
- 在内存应用 Patch，递增 Revision，更新时间，并可追加 Change / Review / Update Batch / Guidance。
- 写入前运行 Schema、跨引用和规则校验。
- 暂存并确认 Presentation Hash 不变后再原子替换。
- 冲突、非法操作、Schema/引用错误或写入失败时不覆盖原 HTML。
- 普通更新只替换 `project-panorama-data` payload，不改 CSS、DOM 或 Renderer JavaScript。

## 7. Schema Findings

Schema 未修改。Finding 与兼容策略见 `docs/schema-findings.md`，包括：

- Intent 可引用但没有稳定 ID
- `data_flow` 缺少一等实体
- Architecture Version 只有 Delta、没有完整成员快照
- 多 Baseline 下 Source 归属歧义
- Resource–Deployment 多向关系可漂移
- External File 凭据与 Credential Reference 缺少强关联
- Removed ID 依赖历史实体保留语义
- Release 缺少 Module artifactVersion 目标映射
- Transition 缺少结构化 Replacement / Compatibility / 共存窗口
- 缺少 Actual Dependency/Interface Snapshot
- Out-of-Scope 只有自由文本
- Baseline changedAreas 没有时间序列

## 8. 验收结论

V0.1 第一轮按 Execution Brief 范围通过验收。Reference Project 可被读取、校验、渲染和安全 Patch；三个主视图、
架构三态、Module Drawer、Runtime/Resource/Access 与 Evolution 信息链均可用；冻结 Schema
与 Reference Data 未被重构或改写；普通数据更新的 Presentation Layer 不变契约有自动测试保护。
设计规范中依赖新增结构化数据的完整规则分支不宣称完成，已作为 Schema Findings 和未实现内容留档。
