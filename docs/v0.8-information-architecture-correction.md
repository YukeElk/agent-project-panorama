# V0.8 控制台 / 演进 / 需求信息架构修正

日期：2026-08-23

状态：实现与源码级验证完成；已纳入 V0.81 发布，Browser Evidence 缺口按 V0.81 审计披露

## 修正结论

1. 控制台从完整需求库存调整为当前阶段决策驾驶舱，展示上一/当前/下一阶段、退出验收、本阶段需求健康度、
   架构迁移及相关风险/决策；
2. 完整需求库存迁入演进页，按“阶段 → 架构层级/功能模块 → 架构版本/迁移 → 发布/验收/部署”展示；
3. Requirement 没有直接 Stage/Layer/Version/Transition 字段，P0 只沿 WorkItem、Release、Module、Transition 的
   精确 ID 链生成只读投影，并明确标记“推导”；
4. 需求详情先展示五段人类影响链和实际开发工作，原始 Trace、JSON Pointer、Trace Gap Candidate、Formal Finding
   收入默认折叠的技术诊断；
5. 原 Gate / Acceptance / Deployment Projection 改为中文“验证 / 验收 / 部署”交付证据链；
6. 新增 P1 数据合同：Requirement Realization 与可重建 Architecture Snapshot。两者尚未进入 Core Schema，页面
   对此显示 Information Gap，不把 Delta/Transition 冒充完整架构版本。

## 发布时保留的视觉边界

应用内浏览器仍受本地 `file://` 导航策略限制。本轮没有通过 HTTP、CDP 或其他浏览器绕过。允许打开候选后应验证：

1. 控制台是否能在首屏判断当前阶段退出条件、未完成需求和迁移风险；
2. “进入完整演进视图”是否保留当前阶段上下文；
3. 需求演进板的四段关系是否清晰，推导标记和架构快照缺口是否不会被误读；
4. 需求详情五段影响链、实际 WorkItem 与 Transition 是否连贯；
5. 原始 Trace 是否默认折叠，同时保持字段路径、缺口候选和正式发现可达；
6. 查看、编辑、讲解、子画布、拖拽连线和跨层吸附是否没有回归；
7. 若后续补采 viewport、Console、Reduced Motion 与打印矩阵，应作为新 Browser Evidence 追加审计；不得回写为
   本次发布时已经存在的机器事实。
