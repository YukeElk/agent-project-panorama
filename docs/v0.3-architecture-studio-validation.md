`SYSTEM → 逻辑架构`，没有增加第四主视图，也没有演化为项目管理平台。

## 浏览器端到端

使用临时 `project-panorama.local.html`、随机 loopback 端口和真实浏览器执行：

1. Bridge capability 启动并自动创建服务端 session；
2. 编辑 `MOD-CONSOLE` 用途，CAS 保存；
3. 正式 Schema / 跨引用 / 风险规则校验通过；
4. 生成绑定 session/candidate/base/source 的 64 位 Proposal Hash；
5. 输入精确批准短语并写入独立 write-once Approval；
6. Apply 创建备份，将 Revision 3 更新为 4；
7. Apply 后数据语义变化，Presentation Hash 保持不变。

真实 Codex CLI 最小结构化评审烟雾测试已成功返回 schema-valid advisory JSON。首次浏览器评审还
发现并修复了 response schema 中 `const` 缺少显式 `type` 的兼容问题，并新增回归测试。若实际
Agent 调用因网络或认证失败，页面会保留可见错误；Formal Validator 与人工治理链仍可继续。

## UI 检查

- 桌面：画布、组件库、属性检查器、数据流和底部治理动作可用；关键 Hash 使用可换行区域展示。
- 移动端 390×844：导航、组件库、需求基线和分层画布可滚动，无横向页面溢出导致的主视图丢失；
  小屏仍以浏览/轻量编辑为主，复杂拖拽建议使用桌面视口。
- 干净页面控制台无 Renderer error/warning。

## 已知边界

- Bridge 是单用户、短寿命的本机开发工具，不是生产服务或多人协作后端。
- Codex adapter 使用只读 sandbox 和最小脱敏投影，但不宣称具有网络、进程树或操作系统级文件隔离。
- 离线草稿不生成权威 Data/Semantic/Layout Hash；这些绑定只由 Bridge 计算。
- V0.3 没有修改 Panorama Data Schema；Architecture Session 与 Agent Review 使用独立 Schema。
