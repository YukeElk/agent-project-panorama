## 1. What moved from Prompt into Skill

以下能力不再依赖用户临时提供长 Prompt：

- 陌生项目先发现 Intent、structured state、implementation、verification、Decision/ADR、runtime/resource 与 narrative evidence；
- 先按 Fact Class 决定 Authority，而不是使用单一全局证据层级；
- 对关键来源执行 Freshness Audit，并保留 Machine/Narrative、Runtime/Historical、Decision/Old Design 等冲突；
- 强制区分 Historical Verification 与 Current Runtime，以及 Planned、Implemented、Deployed、Active；
- 识别 Managed 与 Legacy Panorama，Legacy 默认 COEXIST 且禁止覆盖；
- 从用户能力和约束抽取 Requirement，以责任边界而非目录拆分 Module；
- 独立建模 Current、Target、Transition 与 Module 的 Design/Implementation/Verification/Runtime；
- 尝试从架构变化重建少量 Architecture Versions，证据不足时明确历史不完整；
- 分离 Agent 的 Risk Candidate 与 Validator 的 Formal Finding；
- 生成固定结构 INIT Preview、2–3 个 Next Focus，并在用户 Review 前停止写入。

## 2. Semantic Protocol

新增 `docs/semantic-modeling-protocol.md`，定义：

```text
DISCOVER
→ CLASSIFY EVIDENCE
→ ASSESS FRESHNESS
→ DETECT CONFLICTS
→ MODEL PROJECT
→ INFER CURRENT / TARGET / TRANSITION
→ ASSESS GAPS / RISKS
→ GENERATE INIT PREVIEW
→ HUMAN REVIEW
→ INIT
```

协议包含 Evidence 类别、Fact Class Authority、Freshness 状态、Conflict 格式、九条 Truthfulness Rules、Legacy Strategy、Requirement/Module 协议、四状态推断、Architecture Version Reconstruction、Risk/Finding 边界、Next Focus 与固定 Preview 输出。

`SKILL.md` 将该协议设为已有、Legacy 或复杂项目 INIT 的强制依赖。新建极简项目仍可走最小骨架，但不能用该路径绕过复杂项目 Preview Gate。

## 3. Deterministic Tool Support

新增只读 `scripts/discover_project_evidence.py`。脚本负责：

- project-root 内文件发现与格式识别；
- evidence candidate 轻量分类；
- Git branch/head/dirty metadata、mtime 与 size；
- generated hint；
- Managed/Legacy Panorama marker hint；
- Secret-risk 与 Knowledge Base 路径识别；
- source-root 与 top-level inventory；
- 排除 symlink 越界、常见依赖/缓存目录及整个 `evals/` Oracle 目录。

脚本不修改项目、不调用网络、不读取 `.env`/私钥/credential value 或正式知识库正文、不访问 root 外路径，也不宣布某个来源是真相。非知识库 HTML 可为 marker detection 读取 bounded prefix；其余输出只基于候选与元数据。

## 4. What remains LLM judgment

以下能力明确保留给 Agent：

- source authority 与 freshness 的最终判断；
- 冲突的时间、环境和范围解释；
- Requirement 抽象；
- Module 责任边界与粒度；
- Architecture Version reconstruction；
- Current / Target / Transition 推断；
- Risk Candidate 解释；
- Next Focus 排序与推荐。

Python heuristic 不自动理解架构。所有低置信度结论必须保留 unknown、not_detected、not_observed、draft、proposed 或 pending，并等待 Human Review。

## 5. Anti-overfitting

- 生产 `SKILL.md`、Semantic Protocol 与 discovery script 不包含 case 名称、特定问题编号、特定数据库/模型名或固定项目文件路径。
- Discovery 使用通用 evidence kind、文件格式、命名信号与 marker，不识别项目名称，也没有特殊分支。
- `evals/` 被 discovery script 明确排除，正常 Skill 调用也被禁止读取。
- Case 目录只保存抽象 invariants，不保存完整 Oracle Preview、模块清单、技术栈答案或详细 Oracle Prompt。
- 自动测试扫描生产语义文件中的 case-specific shortcut token，并验证 inventory 不暴露 `evals/` 路径。

本轮没有 clone、读取或执行任何新的 case 对照实验。

## 8. Remaining limitations

- Evidence Discovery 只给 Candidate 和提示；分类或 Legacy cue 可能存在 false positive/negative，必须由 Agent 复核。
- 工具不观察真实 runtime、不执行测试、不查询 CI 或网络；CURRENT_RUNTIME 和 VERIFICATION 仍需要用户授权的当前证据。
- Freshness 与 Authority 没有可靠的通用算法，仍取决于 Agent 对时间、范围和来源的解释。
- Schema 0.1 没有新增 Freshness/Conflict 一等字段；INIT Preview 可以表达这些信息，但正式数据只能映射到现有实体、Reference、Risk、Decision 与 extensions。
- 本轮只准备 Harness，没有执行 blind semantic eval；Bare Skill 的真实分数和 Human Correction Load 尚未知。
- Skill 仍需要用户对 INIT Preview 作最终裁决，不能自主批准 Target、Review、Deployment 或 Runtime 状态。
