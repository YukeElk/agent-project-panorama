# Agent Project Panorama V0.1.4 Evidence & Materialization Report

## 1. Problem Statement

V0.1.3 Blind Semantic Eval 得分 85/100、Critical Fail 为 0，证明 Semantic Modeling 主流程已经能够理解陌生项目。本轮问题转向两个落地缺口：项目自有 Current Operational Evidence 在 knowledge root 中可能被过度保护；批准后的 INIT Preview 没有确定性物化 Initial Review、Change、UpdateBatch、Attention 与 Guidance，导致 Validator High 与 CONTROL 首屏不一致。

## 2. Operational Evidence

Discovery 新增 `accessClass` 与 `operationalMetadataHint`，但仍保持 metadata-only。新增 `scripts/inspect_operational_evidence.py`，只对已资格化的 Project-owned Operational Metadata Candidate 做 project-root confined、bounded、只读解析，并返回结构化 facts、summary、redactions、omitted fields、warnings、hash scope、observedAt 与 provenance。

Knowledge root 内的 registry/state/audit/generated status 可在路径/语义与安全格式双信号成立时进入 Inspector；普通知识正文继续拒读。

## 3. Access Classes

实现五类访问边界：

- `PUBLIC_PROJECT_EVIDENCE`；
- `PROJECT_OPERATIONAL_METADATA`；
- `PROJECT_CONTENT`；
- `SECRET`；
- `EXTERNAL_PRIVATE_DATA`。

Access Class 只决定可用读取路径，不代表 Fact Authority。Operational Metadata 仍需结合 Freshness、环境和 provenance 判断是否支持 Current 状态。

## 4. Secret / Project Content Safety

JSON、JSONL、YAML、TOML 与 generated Markdown Frontmatter 使用 bounded safe parser。password、token、secret、API/private key、credential、authorization、cookie、session 等键递归替换为 `***REDACTED***`；body、content、text、article、message、notes、description 等正文型字段从 Operational Facts 省略。

Inspector 拒绝绝对路径、root escape、符号链接、Secret-risk 文件、普通 Project Content 与不合格 Candidate。Structured 文件超过上限时 fail closed；generated Markdown 只提取 bounded prefix 中的状态行，不返回原始正文。

## 5. Runtime / Verification Observation

新增 `scripts/observe_project_runtime.py`，允许只读观察：

- Git HEAD、branch、dirty、状态条目数量与状态 Hash；
- project-relative 文件存在性；
- 顶层 Python dependency availability（不执行 import）；
- 指定 process name 与 scheduler name 状态；
- 项目 manifest 明确声明的 safe test command。

Process observation 不读取 PID 参数或环境。Safe test 使用 `shell=false`、最小环境、超时、命令过滤和前后项目文件快照；不返回 stdout/stderr 内容。安装、构建、下载、上传、URL 或 package manager 命令被拒绝。已有 report 使用 `historical_test`，主动执行的安全测试使用 `current_test`。

## 6. INIT Materialization Contract

新增 `docs/init-materialization-contract.md` 与 `scripts/materialize_init.py`。内部 `approved-init-model.v0.1` 绑定完整 Preview、canonical `previewHash`、Source Snapshot、真实 `approvedBy/approvedAt`、Evidence Inventory、语义 Change Intent 和 Guidance。

Materializer 验证 Model Version、重新计算 Hash、验证 Approval、比较 Source Snapshot、映射批准数据、运行 Validator、分类/聚类 Finding，并在最终 Schema/Cross-reference 校验后原子写出首版 JSON。Source HEAD 或 dirty snapshot 变化会停止并要求重新 Preview/批准。

## 7. Initial Review / Change / UpdateBatch

确定性 ID 来自 Preview Hash prefix：

- `REV-INIT-*`：approved Panorama Update Review；requestedAt 使用 Preview T1，reviewedBy/reviewedAt 使用真实批准动作 T2；
- `CHG-INIT-*-NN`：只映射已批准的语义 Change Intent，不按字段制造 Change；
- `UPD-INIT-*`：applied Initial UpdateBatch，revision `0→1`，关联 Review、Changes、Attention 与 Guidance option IDs，并写入 `meta.latestUpdateBatchId`。

Synthetic complex project 验证 Review、3 个语义 Change、UpdateBatch 与 Guidance 均被完整物化；相同模型与 Source Snapshot 重复运行得到相同 Data。

## 8. Finding Reconciliation

Materializer 只对实际 `validate_data` 输出分类：

- `PROJECT_GAP`；
- `PANORAMA_EVIDENCE_GAP`；
- `PANORAMA_MODEL_GAP`；
- `CONTROL_BLOCKER`；
- `INFORMATIONAL`。

Verification Finding 若存在相关、可用 Access Class 的 VERIFICATION Evidence，则为 `PANORAMA_EVIDENCE_GAP`；没有证据时为 `PROJECT_GAP`。明确 blocked Transition 为 `CONTROL_BLOCKER`。完整分类与 evidence paths 保存在 UpdateBatch extensions，不修改 Schema。

## 9. CONTROL Attention

只有 High/Critical、非 Informational Formal Finding 进入 Initial Attention，并按业务优先级、Finding Code 与 Class 聚类。核心回归构造 2 个 Module Verification High 与 1 个 blocked Transition High：Formal High = 3，CONTROL Attention = 2（Verification Evidence Mapping cluster + Transition Blocker），且保留全部 relatedEntities。

一致性 Gate 保证 actionable High/Critical > 0 时 Attention 不得为空，从而消除“Validator 有 High，但 CONTROL 显示没有关注事项”的状态。

## 10. Release Semantics

只有 `status=deployed` 的 Release 可以写入 `project.currentReleaseId`。planned/development/candidate/retired Release 仍保留为实体，但若被误设为 current，Materializer 确定性设置 `currentReleaseId=null`，并在 UpdateBatch extensions 记录 `candidateReleaseNormalizedFrom`。

Synthetic case 的 `REL-001 status=candidate` 被保留，但不再冒充当前正式发布。

## 15. Remaining Limitations

- Operational qualification 有意 fail closed；不常见的 operational 目录或文件名可能需要人工确认后才能读取。
- Structured metadata 超过 256 KiB 时拒绝解析；generated Markdown 只读取 64 KiB prefix。大规模 registry 需要未来设计分页/分片，而不是扩大无限读取。
- YAML/TOML Inspector 依赖 PyYAML；Python 3.10 还需要 tomli。脚本不会自行安装依赖。
- Active test 安全依赖项目 manifest 的真实声明；当前实现使用命令过滤、最小环境、无 shell、超时、无输出回传与文件快照，但不是 OS 级网络/文件系统 sandbox。成本高、会写入或来源不明的命令仍必须保持 not_observed 并等待明确授权。
- Process/Scheduler 只报告指定名称的观察结果；`not_detected` 不能证明不存在。
- Evidence Inventory 与用户批准动作使用 Hash/结构校验而非公钥签名；其真实性仍依赖受控 Preview/Review 工作流。
- Materializer 只处理 revision 0、无既有 Review/Change/UpdateBatch 的正式 INIT；既有 Managed Panorama 必须继续走 Proposal/Apply。
