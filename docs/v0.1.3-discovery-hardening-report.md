# Agent Project Panorama V0.1.3 Discovery Hardening Report

## 1. Review Findings Addressed

- Target evals false exclusion：目标项目自身的 `evals/` 不再被目录名全局排除，并可作为验证证据候选进入 Inventory。
- Implementation root coverage：新增基于约定目录与代码密度的实现根候选发现，覆盖非标准目录、工具脚本目录和根级代码。
- Machine/generated status classification：明确状态型文件名现在提供 `machineStateHint`，并与 `generatedHint`、Legacy Panorama Hint 分开表达。

## 2. Root Cause

- `evals` 原先位于全局排除集合，目标项目的验证资产与执行 Skill 自身的 Semantic Eval Oracle 没有边界区分。
- `sourceRoots` 只识别少量固定目录名，无法回答陌生项目的实际代码主要位于何处。
- `dashboard` 曾同时作为普通 Narrative/Legacy cue，状态型 Markdown 又没有独立的机器状态候选信号，导致初始 Authority Hint 偏弱或冲突。

## 3. Implementation

- 从 `EXCLUDED_DIRECTORIES` 移除 `evals`。发现器从当前生产脚本的真实路径推导 executing Skill root，仅当 `<executing_skill_root>/evals` 落在扫描根内且真实存在时才隔离该目录；`scan.excludedSelfOraclePaths` 提供审计记录。测试可通过 `self_skill_root` 注入同一边界，而无需硬编码安装路径。
- `eval/evals/evaluation/benchmark` 下的结构化、叙述和代码文件可作为 test/verification evidence candidate；该分类不将其提升为生产实现。
- `repository.implementationRoots` 汇总顶层与必要的第二层目录，综合 conventional source root、代码文件数量和 code/non-code density。每项只输出路径、代码数量、语言、最多 5 个样例路径和信号；不读取代码内容。
- `tests/test/evals/benchmark/fixtures` 不参与生产实现根计算，`node_modules/vendor/.venv/build/dist` 继续在扫描入口处排除。没有源码目录的小项目可用 `.` 表示根级实现候选。
- `dashboard/status/status-report/health-report/build-status/release-status/runtime-status/system-status` 等强文件名得到 `kind=state` 与 `machineStateHint=true`。`generatedHint` 仍只由既有路径或受限 HTML 内容证据触发。
- 单独的 `dashboard` 不再触发 Legacy；`project-overview.html`、`architecture-overview.html`、`project-guide.md` 和 Panorama 命名仍保留 Legacy Hint。`docs/dashboard-design.md` 保持普通 narrative candidate。

## 4. Safety Boundary

- no network：发现脚本只访问本地文件元数据和本地 Git 元数据。
- no secret read：Secret-risk 与 knowledge-base 文件保持 metadata-only；Implementation Root 只统计路径与格式。
- no root escape：解析后的路径必须位于扫描根内，符号链接不跟随。
- metadata-first：除既有、受限的 HTML marker prefix 外，不读取 Markdown、结构化数据或代码正文来完成发现。
- no architecture inference：输出仍是 evidence candidate、hint 与 implementation root candidate，不生成 Module、Current Architecture、Target Architecture、Requirement 或 Next Focus。
