# V0.4 P2 Verification Receipt Adapter Validation

日期：2026-08-14

范围：独立 Receipt Schema、脱敏与绑定门禁、Mapping Preview、Proposal / Approval / Apply、
Gate / Acceptance Drawer 时间线，以及桌面与移动端交互。

## 实现合同

- Receipt 固定为 `panorama-verification-receipt.v0.1`，使用独立 Draft 2020-12 Schema；未修改
  Panorama Schema。
- Adapter 只接收脱敏摘要、Evidence 元数据、External Finding、Isolation 和 Redaction 声明；
  不执行测试、不读取日志正文、不调度 Agent。
- 输入先经过 1 MiB、20 层嵌套、Schema、敏感明文、Receipt Hash、Project / Revision / Data /
  Source Binding、Evidence 路径与实体 ID 检查。
- Preview 只生成候选 `Reference(test_report)`、Gate / Acceptance Evidence mapping；Schema 0.2
  额外生成 `authority=declared` 的 Fact Provenance 与 Receipt-owned Observation Batch。
- External Finding 始终显示为外部声明，不使用 Panorama Formal Finding Code。
- Proposal 继续使用既有精确 Hash、write-once Approval、Revision / Data / Source /
  Presentation 保护；Receipt 的 `passed` 不会自动修改 Gate 或 Acceptance 状态。

## 浏览器端到端

入口：随机端口 `127.0.0.1` Bridge launcher → capability 保护的 Panorama document →
`系统 → 架构来源 → Verification Receipt Adapter`。

1. 导入 `examples/verification-receipt.v0.1.json`，Preview 为 `ready`，Mapping 后的 Formal Validation
   为 0 error / 28 warnings；`not_enforced / not_executed` 原样显示。Warning 是 Reference 项目已知风险，
   页面读取 Validator 的 `validation.counts`，不会错误压缩为 0。
2. 生成 7 operations、3 affected entities 的普通 pending Proposal。
3. 原生 Dialog 要求输入完整 64 位 Proposal Hash 确认短语，并生成独立 write-once Approval。
4. Apply 在私有 `.local.html` 副本上将 Revision `3 → 4`，创建备份并保持 Presentation。
5. 重载后 Gate Drawer 显示 Receipt、Verification、External Finding、Isolation、Redaction 和
   治理边界；`GATE-WS-CONC` 仍为 `not_configured`，Acceptance 仍未被接受。
6. 1024px 与 390×844 视口无页面横向溢出；移动端系统模式、来源刷新和 Receipt 主操作为
   44px 触控目标；页面 console 为 0 warning / 0 error。

## 边界

- P2 标记为 Experimental；它不证明外部 producer、测试环境或隔离声明可信。
- Receipt 是验证结果投影，不是不可变的完整 Run Journal、评测平台、自动选优器或治理执行器。
- Panorama Schema 0.1 没有 Fact Provenance / Observation Batch，只能保留 Reference extension；
  富结构历史仍由 SF-27 管理，未在本轮重构。
- 本记录是发布候选浏览器与自动化证据，不是完整 WCAG 或跨浏览器认证。
