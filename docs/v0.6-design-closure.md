## 1. 闭合结论

V0.6 使用一套 Evidence-bound Model IR 和一套 View IR，不为每种图建立独立事实 Schema：

```text
Valid Panorama Core / Event Checkpoint / Source Observation
                         ↓ deterministic, read-only
                    Panorama Model IR
                         ↓ bounded profile compiler
                    Panorama View IR
                         ↓ layout excluded from semantics
                Candidate Renderer / Verified Delivery
```

四层边界固定为：

1. Core/Event/受信 Source Observation 保存或绑定工程事实；
2. Model IR 只归一化实体、关系、来源、时间和 Unknown/Conflict；
3. View IR 只选择子图和阅读语义；
4. Layout/Viewer State 只控制坐标、主题、缩放和选择。

Model/View IR 均是可删除、可重算的候选，不允许反向 Apply 到 Panorama，不生成 Review、Approval、Finding、
Gate、Acceptance、Deployment 或 Current Runtime 事实。

## 2. 本轮冻结的机器合同

- [`panorama-model-ir.schema.v0.1.json`](../schema/panorama-model-ir.schema.v0.1.json)：稳定实体/关系身份、
  Evidence Pin、Source/Event/Project/`asOf` Binding 和 Model Semantic Hash；
- [`panorama-view-ir.schema.v0.1.json`](../schema/panorama-view-ir.schema.v0.1.json)：View Profile、Model
  Binding、Node/Edge exact reference、Semantic/Layout Hash 分离；
- [`source-topology-observation.schema.v0.1.json`](../schema/source-topology-observation.schema.v0.1.json)：
  Inventory、Source Element/Relation、Evidence、Currentness 与 Semantic Hash；
- [`extraction-receipt.schema.v0.1.json`](../schema/extraction-receipt.schema.v0.1.json)：输入/输出/Loss Binding、
  Adapter 状态、计数与可证明安全陈述；
- [`panorama-model-ir-contract.md`](panorama-model-ir-contract.md)：输入、身份、Evidence 与验证规则；
- [`panorama-view-ir-contract.md`](panorama-view-ir-contract.md)：投影、Scope、Layout 与 Cross-reference 规则。

机器 Schema 只为已有实现冻结。Source Observation 与 Extraction Receipt 已在 Repository Inventory、Python、
JS/TS、Manifest、Loss 和 Model IR 消费者端到端通过后冻结。Renderer Delivery Receipt 仍只由行为合同约束，
必须等待真实 Renderer/故障测试，避免创建没有消费者的空壳。

## 3. Slice A 实现范围

当前实现链：

```text
Panorama Core + optional bounded Source Observation
  → Formal Core/Observation Validators
  → authored architecture + source_element/dependency candidates
  → panorama-model-ir.v0.1
  → module profile + one architecture scope
  → panorama-view-ir.v0.1
```

当前明确支持：

- authored Module/Connection ID 原样成为 Model Identity；
- Layer 按 current/target/historical 分别绑定，Target 不复用错误的 Current Layer；
- JSON Pointer + entity digest + Panorama Data Hash 形成 Evidence Pin；
- 离线 Source 固定显示 `recorded_as_of`，并保留 `source_currentness_not_verified`；
- 未提供 Event Checkpoint 时保留 `event_checkpoint_not_provided`；
- Current/Target 模块视图只包含端点均存在且 Scope 匹配的正式 Connection；
- Layout Hash 与 View Semantic Hash 分离；
- Schema、Hash、ID、端点、Layer、Evidence 与 Model Binding 任一错配均 fail closed。
- Repository Inventory 绑定 Git HEAD 或完整 Content Digest；Python AST、JS/TS 有界静态 import、
  package/pyproject dependency 均输出 Evidence/Resolution/Loss；
- Source Element 不提升为 Module，static dependency 不提升为 runtime call/sequence；
- 已分类 Secret 路径拒绝读取，普通源码仅瞬时解析且不持久化；Receipt 不伪造 embedded Secret scan。

当前仍没有实现：

- 完整 JS/TS parser、调用图、container/CI/deployment 配置或作者模型导入；
- System Context 独立编译器、正式 authored data-flow importer 或 runtime trace importer；
- 层级聚合/展开、通用容器/CI/Runtime Trace importer；
- 通用 Engineering Event Capture Adapter 或 Source Currentness 实时确认；
- Verified Delivery、last-good、独立人工视觉 acceptance、Export、RAG、Eval 或后训练。

当前已实现但尚未发布：

- hash-bound Single HTML Renderer Candidate，六种 View 共用 Evidence Drawer、Search/Focus、上/下游 Trace、
  事实/Scope/Freshness/Risk/Evidence Filter、实体/关系/Event/Trace Deep Link、Pan/Zoom/Fit、主题与键盘路径；
- 分层确定性布局、正交关系路由和独立 Geometry Validator；
- 1440×900、1600×1000、1920×1080、2048×1320 Desktop 机器矩阵，以及 839/430px 窄屏检查；
- 机器状态、Agent 截图复核与独立人工视觉状态分离。精确证据见
  [`v0.6-interactive-renderer-validation.md`](v0.6-interactive-renderer-validation.md)。

## 4. 审批边界

- Model/View Compile、Validate、Diff 和本地新候选输出属于 Read-only/Automatic Quality，不需要逐次批准；
- 覆盖既有候选文件需要显式 `--overwrite`，但不会修改正式 Panorama；
- 把 Derived/Declared 架构采纳为正式 Current/Target/Decision 仍须准确 Proposal Hash 的人工批准；
- Source Hook、Policy、last-good Promote、公开发布与外部导出继续使用独立门禁。

last-good、Proof Lab 和独立人工视觉 acceptance，之后才进入 V0.6 Release Review。
