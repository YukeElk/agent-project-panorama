## 3. Bug 修复

### Approval 与 Apply 脱节

- 问题：批准后仍可能修改 Update Package 的语义字段。
- 根因：旧 Apply 只检查 Revision/Data Hash，没有把完整 Proposal 绑定到用户批准。
- 修改：引入确定性 Proposal Hash 和 Approval 元数据检查，并校验 Change/Review/UpdateBatch 关系。
- 测试：未批准拒绝、批准后篡改拒绝、准确批准通过。

### Next Focus 历史引用失效

- 问题：替换当前 Guidance 后，旧 UpdateBatch 的 Option ID 可能悬空。
- 根因：历史记录引用可变的顶层当前 Guidance。
- 修改：在 v0.1.1 兼容层保留 inactive historical options，并纳入引用校验但不进入当前 UI。
- 测试：连续三次更新后全部历史引用有效，当前 UI 只展示当前 Guidance。

### Secret 默认泄漏

- 问题：Agent 读取 JSON 时可能把 Embedded Secret 写入终端或上下文。
- 根因：读取工具默认返回原始 payload。
- 修改：默认深度脱敏；明文读取必须显式使用不安全开关。
- 测试：Embedded 脱敏、External 不解析、显式明文警告。

### Git Secret Risk 不可见

- 问题：被 Git 跟踪的含敏感数据 Panorama 没有高优先级提醒。
- 根因：Validator 不检查源文件 Git 状态。
- 修改：增加 tracked/staged 检测与 High `GIT_SECRET_RISK`。
- 测试：Reference Project 产生结构化 High Finding；未跟踪本地文件不会误报为已提交。

### 动态 URL 可注入危险协议

- 问题：Reference/Code Path 等动态链接可能包含危险 Scheme。
- 根因：多个渲染分支直接写入 `href`。
- 修改：所有动态链接统一经过 `safeHref()` / `safeAnchor()`。
- 测试：Node 自动测试覆盖 HTTP、HTTPS、相对路径、Windows 路径及 JavaScript/VBScript/Data/FTP 拒绝。

### Optional Gate 错误阻断

- 问题：非 Required Gate 的失败被计入 Verification Gap。
- 根因：Gate 聚合没有先判断 `required`。
- 修改：只有 Required Gate 阻断；Optional 失败为独立 INFO。
- 测试：Required/Optional 组合与 Optional failed 分支。

### Review Gap 噪声

- 问题：实验性 Functional Module 与当前/已发布 Module 使用同一告警等级。
- 根因：规则只按单一成熟度判断。
- 修改：结合 Design/Implementation、Current Scope、Release、Deployment 与 Transition 上下文定级。
- 测试：探索态 INFO、当前或发布态 High。

### 同环境 Deployment 被覆盖

- 问题：一个 Environment 只能展示一个 Deployment。
- 根因：Renderer 使用单值映射。
- 修改：使用 Environment → Deployment List，支持排序和显式选择；CONTROL 聚合全部状态。
- 测试：Reference development 同时包含 Active 与 Deploying；浏览器确认两者均可见并可切换。

### Resource 与实体详情不完整

- 问题：Resource 仅从当前 Deployment 派生，非 Module 实体缺乏统一详情入口。
- 根因：视图依赖局部 Runtime 上下文和 Module 专用 Drawer。
- 修改：增加完整 Resource Pool 与 Generic Entity Inspector。
- 测试：Renderer contract 自动测试；浏览器检查 Resource 筛选、Module 与 Connection Inspector。

### INIT / Proposal 缺少强制校验

- 问题：无效数据可能生成正式 HTML，更新预览依赖手工拼装。
- 根因：初始化与提案没有统一验证和确定性输出。
- 修改：INIT 前后验证；新增最小骨架与 deterministic Proposal 工具。
- 测试：无效输入不落正式文件、最小项目端到端、Proposal→Approval→Apply。

## 6. Security

- Secret Redaction：默认读取不输出 Embedded 明文；External File/Store 不自动解析。
- Git Risk：tracked/staged + Embedded 产生 High `GIT_SECRET_RISK`；`.gitignore` 增加 `*.local.html`。
- URL Sanitization：动态 href 使用白名单，危险或未知 Scheme 保持可读但不可点击。
- Approval Hash：用户批准绑定完整 Proposal 语义；批准后篡改、过期 Revision/Hash 和提交前并发变化都会拒绝 Apply。
- Apply Safety：使用同文件独占锁、备份、临时文件、原子替换和提交前 CAS 复核；普通更新只替换 `project-panorama-data`。

### 产品场景复核

1. CONTROL：30 秒内可读出当前阶段、最近更新、重大变化、验证/评审状态、Next Focus 选项及推荐原因。
2. Module：可读出 Purpose/Rationale、Source/Baseline、Current/Target、技术、责任、Acceptance、Gate、Risk、Decision、Code Path、Deployment/Resource。

5. 长期运行：Secret 默认输出与多 Deployment 隐藏问题已解决；Next Focus 由兼容层保留。历史 Architecture 的不可变重放和大量 Local Change 的长期压缩仍需 V0.2。

## 8. 仍存在的问题

- V0.1 Architecture Version 只有 Delta，没有不可变完整成员快照；半年后无法仅靠某一版本对象稳定重放当时完整拓扑。
- Next Focus 历史记录当前位于 `guidance.extensions.historicalOptions`，能防悬空但不是最终所有权模型。
- Release 缺少按 Module 的 immutable artifact manifest，无法严格验证 artifactVersion 是否符合 Release 声明。
- Resource/Deployment 关系有多份可漂移副本；Validator 只能发现可证明的不一致。
- Reference Project 仍有 29 个可操作 Warning；9 个 High 主要来自待补 Review/Verification 与 tracked demo Embedded credential。它们是演示数据的真实风险，不应静默清零。
- 本轮只完成 Chromium 1440px/1024px UI 检查，没有跨浏览器矩阵。
- 尚未用一个运行半年的真实 Agent 项目验证信息增长、Local Change 压缩与历史解释质量；V0.1.1 完成后才具备进入该试运行的控制安全条件。

## 10. V0.2 Migration Proposal

仅提出方案，不执行：

1. 新建 Schema v0.2，不覆盖 v0.1；提供独立 migration/rollback 与双版本 validator fixture。
2. 将每次 Guidance Options + Recommended/Selected 快照固化到 UpdateBatch，迁移 `historicalOptions`。
3. 为 Architecture Version 增加 immutable membership snapshot，同时保留 Delta 作为解释层。
4. 为 Release 增加按 Module 的 Artifact Manifest。
5. 引入结构化 Replacement/Compatibility/Coexistence deadline。
6. 明确 Resource/Deployment 单一事实源并把反向关系定义为派生数据。
7. 归一化 External Credential Reference，并为 Intent 建立 Stable ID。
8. 对 Data Flow、Actual-vs-Declared 与 Local Change 历史压缩分别做 Schema Finding 驱动的设计决策。
9. 使用真实长期 Agent 项目做迁移前后对照，验证历史可重放、Presentation 不变、Secret 不泄漏与回滚无损。
