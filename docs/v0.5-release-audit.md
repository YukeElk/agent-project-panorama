# V0.5.0 Release Audit

日期：2026-08-20

审核对象：Engineering Event Foundation Slice A、Approval Policy Core，以及显式 opt-in 的
Proposal/Apply Governance Outbox。

## 结论

**本地发布候选审核通过；正式 Tag / Release 仍为条件性 No-Go。**

阻断发布的 P0/P1 代码问题已经修复并由负向测试覆盖。当前可以形成 V0.5.0 候选 Commit 并进入远程 CI，
但现在的 HEAD 仍是 `aad53750c4c927c3f93da929efbe4ded2cb84510`（`v0.4.0`），工作树包含尚未提交的
V0.5 变更，因此还没有可发布的 V0.5 Commit 身份。远程 CI、Linux 符号链接用例和 Tag 均未执行。

## 候选范围

V0.5.0 只包含：

1. Project-local Engineering Event Schema、Store、Validator、Head 与显式恢复；
2. Approval Policy Prepare、exact-hash Approval、Materialize、Activation、Use Ledger、Receipt/Event、
   Revocation、Supersede 与 Store Recovery；
3. 普通 Proposal/Apply 的显式 opt-in、fail-closed Governance Outbox。

Observation、Verification Receipt、Validation Manifest、Event Head、Verified Delivery、Renderer 与
Freshness 的 Delegated Policy Adapter，以及 View IR、Renderer 改版、Dataset/RAG/Eval Export、后训练和
Agent 平台均不属于本候选版本。

## 已知限制

- Hash 提供完整性检测，不提供外部签名或主机级防篡改；Store 访问控制仍由项目环境承担。
- Node 在本机不可用，Renderer/Node 门禁必须由远程 CI 或具备 Node 的发布环境补齐。
- Windows 当前环境无法创建测试符号链接；路径逃逸逻辑已有其他本地测试，但该用例必须在 Linux CI 通过。
- Governance Outbox 只有显式提供 Event Store 时启用；其他 Capture Adapter 未实现。
- Installed Skill 与正式 Git Release 尚未更新，不能把源码工作树状态视为已发布能力。

## 正式发布门禁

1. 审查并提交当前 V0.5.0 候选范围，建立新的候选 Commit 身份；
2. 推送候选分支并要求 GitHub Actions 全绿，包括 Linux 符号链接和 Node 门禁；
3. 复核提交后的干净工作树、版本说明、候选 Commit 与 Tag 指向；
4. 远程 CI 通过后再创建 V0.5.0 Tag / Release；
5. 最后单独验证并安装 `agent-project-panorama` Skill，避免开发源码与已安装副本漂移。

在以上门禁完成前，不创建最终 Tag、不发布 Release、不把 Installed Skill 标记为 V0.5。
