# V0.8 RC2 单画布融合设计

状态：已被父子语义画布方案取代；仅保留为 RC1→RC2 问题诊断记录，不再作为实现规范

> 2026-08-23：用户后续确认产品只保留“阅读 / 编辑”两种模式，讲解属于阅读模式内的镜片；
> 架构主画布与模块内部逻辑子画布形成两级语义导航。后续实现以
> [V0.8 父子语义画布具体实施计划](v0.8-parent-child-semantic-canvas-implementation-plan.md) 为准。
> 本文中的“三种工具状态”和“六个并列投影”不再是规范要求。

适用范围：Agent Project Panorama Skill、Codex 终端、Renderer 0.4/V0.8 候选

## 1. 重新评审结论

V0.8 RC1 不满足视觉验收，不能继续发布。三个问题均成立：

1. 全景查看、全景讲解和 Architecture Studio 虽在同一 HTML 中，但使用不同图形运行时、不同布局和不同选择状态；它们不是同一张画布。
2. 正式 Layer、Module 只有技术名称，Renderer 没有可追溯的中文显示名来源，导致主扫描层仍以英文为主。
3. Guided 与 Studio 画布以 `overflow:auto` 为主要导航方式，没有完整的相机模型，不能自然地自由平移、缩放和定位。

根因不是按钮位置或 CSS 风格，而是页面内部同时存在三套图形实现：

- 正式查看由 `renderLogical()` 和 Architecture Board 负责；
- Studio 由独立 Candidate Canvas 负责；
- 全景讲解由 `panorama-guided-host.html` 中的独立 Custom Element、独立 `layout()` 和 `graphHtml()` 负责。

继续同步三套坐标只能降低表面差异，不能消除身份、布局、选择、详情和播放状态漂移。因此 RC2 必须删除重复画布运行时，把“查看 / 讲解 / 设计”重定义为同一画布上的三种工具状态。

## 2. 产品定义

页面保留 `控制台 / 系统 / 演进` 三个主视图。进入系统或演进中的图形视图后，用户始终面对同一个 Canvas Runtime：

```text
┌ 投影与范围：模块 / 数据流 / 部署 / 时序 / 生命周期 / 演进风险 ─ 当前/目标/迁移/历史 ┐
├ 工具：查看 | 讲解 | 设计 ─────────────── 搜索 ─ 缩放- / 100% / 缩放+ / Fit ┤
├───────────────┬────────────────────────────────────────┬───────────────┤
│ 分组/图例       │                                        │ 上下文详情栏     │
│ 可折叠          │        唯一 Canvas World                │ 查看/讲解/设计   │
│                │  同一节点、连线、分组、坐标、相机与选择    │ 只更换内容与动作 │
├───────────────┴────────────────────────────────────────┴───────────────┤
│ 业务流程播放：场景 / 上一步 / 播放暂停 / 下一步 / 速度 / 进度（按需展开）          │
└────────────────────────────────────────────────────────────────────────┘
```

三个工具状态不再对应三个页面或三个 DOM 图：

- **查看**：浏览正式事实、证据、状态、关系、风险与决策。
- **讲解**：在当前图的原节点和原连线上叠加聚焦、遮罩、步骤和讲解详情。
- **设计**：在当前图上进入隔离的 Candidate Source，以差异覆盖层编辑节点、连线、层级和布局。

切换工具不得重建另一张图，不得改变节点坐标、相机位置和选择对象。

## 3. 单一状态模型

统一运行时使用以下正交状态，不再以 `systemMode` 分派三套 Renderer：

```text
sceneSource = formal | candidate
tool        = inspect | explain | design
projection  = module | dependency_dataflow | deployment_runtime |
              sequence | lifecycle | evolution_risk
scope       = current | target | transition | historical
camera      = { x, y, scale }
selection   = { viewId, nodeId?, edgeId?, entityRef?, relationRef? }
explain     = { storyId?, stepIndex?, focusNodeIds[], focusEdgeIds[] }
playback    = { scenarioId?, stepIndex, status, speed }
```

强制不变量：

1. `tool` 切换只改变覆盖层、详情栏和可用操作，不替换 Scene 或 Canvas Runtime。
2. 同一 View 内切换工具后，节点和连线几何差值必须为 0，选择与相机保持不变。
3. `projection/scope` 切换仍由 View Set 加载另一份已验证 View IR，但使用同一 Runtime；若新 View 不含原对象，必须明确提示“该对象不在当前投影”，不得按名称猜测映射。
4. `camera`、选择、播放进度和讲解步骤均为 Viewer State，不进入 Core、Model、View、Explain Pack 或 Candidate 的语义 Hash。
5. Candidate 节点坐标继续属于 Layout Hash；相机坐标不得进入 Layout Hash。

## 4. Unified Scene Graph

Renderer 在内存中建立只读的统一场景投影，不新增第四套工程事实：

```text
CanvasScene
  binding: projectId + modelId/hash + viewId/semanticHash/layoutHash
  source: formal | candidate(sessionId/candidateId/hash)
  groups: stable group/layer references
  nodes: stable view node ID + entityRef + display/technical labels
  edges: stable view edge ID + relationRef + exact endpoints
  layout: node/group geometry from bound View or Candidate
  overlays: explain focus + playback focus + risk/decision + candidate diff
```

身份规则：

- 正式对象以 `entityRef.type + entityRef.id` / `relationRef.type + relationRef.id` 对齐；
- View Node/Edge ID 只代表该投影中的实例；
- 草稿节点继续使用 session-local `nodeId`，不得冒充正式实体；
- 名称、中文显示名、坐标和 DOM 顺序都不能成为身份。

Explain Pack 必须精确绑定当前 Scene 的 View ID/Hash。Candidate 讲解只有在 Candidate Explain Preview 与 Candidate Semantic/Layout Hash 精确绑定时才可启用；否则显示“候选讲解尚未编译”，不得把正式讲解静默套到草稿图上。

## 5. 自由画布交互

正常桌面模式下 Canvas Viewport 使用 `overflow:hidden`，导航由相机完成：

- 空白区域按住左键拖动：平移画布；
- 空格 + 左键拖动：无论当前工具为何均强制平移；
- 中键拖动：平移；
- 触控单指：平移；
- 滚轮/触控板：以指针为中心缩放；
- 设计状态下直接拖节点：只移动节点并写入 Candidate Layout；空白拖动仍平移；
- `+ / - / 0 / F`：放大、缩小、适配全图、适配选择；
- 工具栏提供等价按钮，保证键盘可达和可发现性。

实现形态：

```text
.canvas-viewport { overflow: hidden; touch-action: none; }
.canvas-world {
  transform: translate3d(cameraX, cameraY, 0) scale(cameraScale);
  transform-origin: 0 0;
}
```

滚动条不再是主导航。打印模式和必要的无障碍降级可提供静态完整布局，但不能影响日常交互。

## 6. 中文名称契约

不得在浏览器中依靠固定词典或大模型即时翻译正式架构名称，因为这会生成无法追溯的显示事实。

RC2 为 authored Layer 和 Module 增加向后兼容的可选字段：

```json
{
  "name": "Business Agent",
  "displayName": "业务智能体"
}
```

规则：

- `name` 保留正式技术名称和兼容性；
- `displayName` 是经作者确认的主要显示名称，进入 Core/Model/View 的语义 Hash；
- 编译器输出 `displayLabel = displayName || name` 与 `technicalLabel = name`；
- 节点和层级主标题优先显示中文，英文技术名/ID 作为次级文本；
- 旧 Core 不含 `displayName` 时继续可渲染，但 authored Module/Layer 显示“缺少中文显示名”信息缺口；
- Source-derived 文件、类和函数不伪造中文名称，使用“源码文件 · orders.ts”“类 · OrderService”等中文类型前缀保留技术身份。

参考案例必须补齐真实中文显示名，例如：

| Technical name | 主显示名称 |
| --- | --- |
| Interaction | 交互入口层 |
| Orchestration | 编排层 |
| Agent | 智能体能力层 |
| Service | 服务层 |
| Data | 数据层 |
| Project Console | 项目控制台 |
| Orchestrator | 编排器 |
| Business Agent | 业务智能体 |
| Direct Vector Access | 向量直连 |
| Retrieval Agent | 检索智能体 |
| Shared Workspace | 共享工作区 |
| Vector Store | 向量存储 |

## 7. 三种工具的详情栏

右侧详情栏是同一 Selection 的不同阅读/编辑层，不得各自维护选择。

### 7.1 查看

默认只展示一条可快速扫描的逻辑链：

```text
设计需求 → 设计原因 → 实现功能 → 系统角色 → 交互方式 → 技术选型
```

状态、证据、风险、决策和原始字段放在可展开的次级区域，不删除原有 Evidence Inspector 能力。

### 7.2 讲解

讲解使用当前 Selection 与 Explain Pack Step，在同一栏补充：

- 当前图的整体目标、范围、主路径和信息边界；
- 当前节点的完整逻辑链；
- 相关节点/关系为何存在、如何交互；
- 风险为什么产生、可能结果、应对措施；
- 决策为什么需要、候选方向、影响和未决条件；
- 随项目修订动态更新后的绑定版本、变化提示和过期状态。

点击讲解中的对象必须聚焦同一 Canvas Scene 中的精确 Node/Edge ID；不得另画一张近似图。

### 7.3 设计

设计工具把正式 Scene 作为基线，只在其上叠加 Candidate Diff：

- 新增：实线高亮或虚线草稿；
- 修改：差异标记与前后值；
- 删除：可识别的幽灵节点/边；
- 冲突/校验失败：独立错误覆盖层。

详情栏提供候选属性、层级归属、连线方向、验证结果和 Proposal 状态。所有改动仍写入隔离 Candidate Session；不绕过 Proposal / Approval / Apply 门禁。

## 8. 业务流程动效

业务流程演示不再拥有独立画布。底部播放器消费 Explain Pack 中精确绑定的 `playbackScenarios`，在当前 Scene 原节点和原连线上执行：

- 步骤开始时聚焦对应节点/边；
- 粒子或描边沿真实 Edge Path 运动；
- 详情栏同步显示本步输入、处理、输出、风险和证据；
- 播放切换 View 时必须使用场景声明的精确 View Binding；
- 暂停、重播、速度、Reduced Motion、页面隐藏暂停和有限完成规则保持不变。

若流程步骤引用的节点/边不在当前 View 中，编译或渲染必须 fail closed，不得通过名称搜索或临时绘制代理边补齐。

## 9. 实现工作包

### WP0：RC1 收口与合同修订

- 将当前 V0.8 RC1 标记为视觉验收未通过，不发布、不打 Tag；
- 修订 Renderer、View、Studio、Explain 和 Business Flow 合同，加入单 Runtime 不变量；
- 为单画布增加独立 Finding 与验收矩阵。

### WP1：统一 Scene 与相机

- 抽取 `CanvasSceneAdapter`、`CanvasStore` 和 `CameraController`；
- 先迁移正式查看，完成自由平移、指针中心缩放、Fit 与深链恢复；
- Camera/Selection 只保存在 Viewer State。

### WP2：讲解迁移

- 移除 Guided Host 中独立 `layout()`、`graphHtml()` 和 Canvas DOM；
- 将 Story/Step 转换为 Overlay + Rail Controller；
- 验证切换查看/讲解时几何、相机和选择保持不变。

### WP3：Studio 迁移

- 复用同一 Scene Runtime，Candidate 作为 Source/Diff Overlay；
- 迁移节点移动、连线、层级和 Inspector 操作；
- 保持 Semantic/Layout Hash、Session Journal、Validation、Proposal 与 Apply 合同不变。

### WP4：中文显示名

- 为 Core 0.1/0.2、Model IR、View IR、Architecture Session 增加向后兼容 `displayName/displayLabel/technicalLabel`；
- 更新编译器、Validator、Renderer 和 Reference Fixtures；
- 把缺失 authored 中文名作为显式信息缺口，而不是机器猜测。

### WP5：流程播放融合

- 将播放器迁移为 Canvas Overlay；
- 使用同一 SVG/Canvas Edge Path；
- 完成暂停、重放、速度、Reduced Motion 与 stale binding 测试。

### WP6：多项目视觉与治理验证

- 至少覆盖 AI Wiki、Spring PetClinic 和 Backstage Slice；
- 六类 View、四种 Scope、正式/候选两种 Source 均纳入矩阵；
- 生成新的 Verified Delivery Candidate，并重新请求精确人工视觉批准。

## 10. RC2 验收门禁

以下条件全部通过后才可再次进入发布评审：

1. 页面任一时刻只有一个图形 Runtime 和一个 Canvas World；查看/讲解/设计切换不创建第二套节点图。
2. 同一 View 切换三种工具后，全部 Node/Edge 边界框坐标差为 0；Camera 与 Selection 不变。
3. 讲解 Step、节点详情和流程播放均指向当前 Scene 的精确 Node/Edge ID。
4. 1440×900、1600×1000、1920×1080、2048×1320 下不依赖横向或纵向滚动条导航画布。
5. 空白拖动、Space+拖动、中键拖动、触控平移、指针中心缩放、Fit All、Fit Selection 和键盘等价操作通过。
6. 代表项目 authored Layer/Module 的中文主显示名覆盖率为 100%，英文技术名/ID 保留在次级层。
7. 六类 View 均使用同一 Runtime；空 View 清空选择、讲解和播放上下文。
8. Studio 编辑只改变 Candidate；Camera 不进入 Layout Hash，节点坐标不进入 Semantic Hash。
9. Candidate Explain Preview 的 Hash Binding 不匹配时 fail closed。
10. 流程播放只沿正式绑定 Edge Path 运动，Reduced Motion 与打印模式保留静态语义。
11. 旧 Panorama Core 不含 `displayName` 时可兼容渲染，且不会被 Renderer 自动写回或伪造中文事实。
12. 机器视觉证据只能保持 `visualReview=pending|skipped`；必须由人工检查新候选后精确批准。

## 11. 非目标

- 不新增 React/Vue、通用后端或第四个主导航；
- 不把 Candidate 自动写入正式 Panorama；
- 不从布局、名称或讲解文案推断关系、风险、因果或业务流程；
- 不在 RC2 扩展实时多人协作、无限画布数据库或通用白板；
- 不用运行时自动翻译替代 authored 中文显示名。

## 12. 审批边界

批准本设计只授权进入 V0.8 RC2 实现，不授权 Commit、Tag、Release、Verified Delivery Promotion 或人工视觉接受。实现完成后必须重新提交 Exact Candidate ID、SHA-256、验证矩阵和待人工检查入口。
