## 这次关闭了什么

- Spring PetClinic 不再是“unsupported language → 0 files”案例；Source Body、Evidence、Content Digest、Loss、
  Model/View/Browser/Delivery 已形成端到端闭环；
- `SUPPORTED_LANGUAGE_EXTRACTION` 和 `PUBLIC_SOURCE_VIEW_AND_BROWSER_DELIVERY` 可以关闭；
- 未支持的 Kotlin/Go/Rust/C/C++/C#/Ruby/PHP/Swift/Scala 仍走原有 partial/unknown fail-closed 分支。

## 这次没有关闭什么

Java Import 不是完整源码架构。PetClinic Oracle 还要求 Controller Annotation、直接 Repository 注入、
Thymeleaf/数据库配置、服务层冲突、运行未知和测试未知。当前 Adapter 不生成 Normalized Claim，因此
`supportedFactRecall` 与 `forbiddenClaimAvoidance` 均记录为 `not_scored`，不能用 49/221/468 的数量冒充准确率。

后续应在两个方向二选一或组合：

1. 增加有证据的 Java Annotation/Type Declaration 与 Properties/Maven Configuration Adapter，再对 10 条
   Oracle 逐条评分；
2. 建立 Source Element → Panorama Module 的显式 Mapping Proposal，由人工/规则批准后进入 Current/Target，
   不允许 View Set 或 LLM 自动晋升。

因此公开发布阻塞项从“没有 Java Adapter”收窄为
`PUBLIC_SOURCE_SEMANTIC_COVERAGE_AND_MODULE_MAPPING`，独立人工视觉与最终 Commit Proof Lab 仍未关闭。
