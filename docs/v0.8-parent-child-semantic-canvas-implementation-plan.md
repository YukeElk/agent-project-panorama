# V0.8 父子语义画布具体实施计划

状态：WP0–WP8 实现完成；历史 PVD 接受已被验收后缺陷报告替代；修复候选浏览器验证待完成；Commit/Tag/Release/last-good 尚未执行

适用范围：Agent Project Panorama Skill、Codex 终端、V0.8 后续候选

取代文档：`v0.8-unified-canvas-rc2-design.md` 中“三工具 / 六个并列画布”实现方案

## 1. 本轮要交付的产品结果

V0.8 后续候选只提供一套 Canvas Runtime 和两种模式：

- **阅读模式**：查看正式事实和 AI 基于代码生成的 Current 模块内部逻辑；讲解、进度、风险/决策、证据、数据流和动效都是当前画布的镜片，不另建页面或第二张图。
- **编辑模式**：在同一画布中编辑隔离 Target Candidate；可编辑架构层级、模块、连接，以及模块内部逻辑、边界端口和内部数据流。正式 Current、业务源码和 Panorama Core 在编辑期间不变。

语义导航只允许两层：

1. 项目架构主画布：架构层级/容器、模块、模块间连接和外部资源。
2. 模块内部逻辑子画布：当前模块内部逻辑、输入/输出边界端口，以及紧凑的外部模块/资源引用卡片。

主画布双击模块进入子画布；子画布不展开其他模块内部逻辑。双击外部模块引用时，导航到该模块自己的子画布。滚轮缩放和画布平移只改变相机，不改变语义层级。

## 2. 已冻结的交互与事实边界

### 2.1 统一状态模型

Renderer 使用一套正交状态：

```text
mode              = read | edit
semanticScene     = architecture | module_logic(moduleId)
structuralLens    = base | dataflow | runtime | sequence | lifecycle | evolution_risk
knowledgeLens     = none | explain | progress | risk_decision | evidence | playback
sceneSource       = formal_current | formal_target | candidate
navigationStack   = [{semanticScene, camera, selection}]
camera            = {x, y, scale}
selection         = {nodeId?, edgeId?, groupId?, entityRef?, relationRef?}
```

约束：

- `mode` 或镜片切换不能创建另一套节点 DOM、改变当前场景几何或丢失相机/选择。
- 双击是语义下钻；单击只选择；Enter/Space 提供键盘等价操作。
- 主/子画布各自保存相机，返回父画布时恢复离开前位置。
- 编辑模式只写 Candidate；阅读模式无任何语义写入口。
- 讲解、播放、相机、选择和折叠状态均为 Viewer State，不进入任何语义 Hash。

### 2.2 多视图不再是分开的页面

现有六类 View 被收敛为同一语义场景上的结构镜片：

| 现有 Profile | 新位置 | 主要差异 |
| --- | --- | --- |
| Module | 架构主画布 `base` | 层级、模块、正式通信关系 |
| Dependency/Data Flow | 主画布或子画布 `dataflow` | 强调依赖方向、数据内容、接口与 custody；不制造运行调用 |
| Deployment/Runtime | 主画布 `runtime` | 叠加 Release/Deployment/Resource，继续区分 Declared/Observed |
| Sequence | 当前场景 `sequence/playback` | 按显式 Event/Business Flow 顺序高亮原节点和原边 |
| Lifecycle | 子画布优先的 `lifecycle` | 展示有证据的状态变化、重试、退出和回退路径 |
| Evolution/Risk | 主/子画布 `evolution_risk` | 叠加 Current/Target Diff、事件演进、风险和信息缺口 |

切换镜片只调用同一 Scene Adapter 和 Camera Controller。镜片需要新增资源或引用卡片时，可以重编译 Scene，但不得挂载独立 Guided/Studio 图形运行时。

### 2.3 Current 与 Target

- Current 模块内部逻辑来自源码的有界 AI 归纳，固定标记为 `derived`，并绑定 Git HEAD/完整内容摘要、证据位置、生产者版本、覆盖率、Transformation Loss 和 Information Gap。
- Target 模块内部逻辑是可编排的正式设计候选。编辑模式从 Current 归纳或已有 Target Design 派生 Candidate，但不覆盖 Current。
- Source 变化后旧 Current Observation 立即变为 stale；重新归纳生成新 Observation。已有 Target Candidate 保留，但其 Formal Validation、Explain Preview 和 Proposal 变为 stale。
- 浏览器不直接调用模型，也不在运行时自由续写讲解；Codex/Skill 在受控编译阶段生成并校验候选制品。

## 3. 数据与契约修改决策

### 3.1 新增 Current 只读 Sidecar

新增 `module-logic-observation.v0.1`，至少包含：

- Project、Module、Panorama Revision/Data Hash、Source/Git Binding、`asOf`、Producer/Contract Version；
- 内部逻辑节点、逻辑边、边界端口、外部引用；
- 每个节点/边的 Evidence Pin、authority、confidence、事实状态和解释边界；
- coverage、unresolved、information gaps、Transformation Loss；
- 删除 `integrity` 后的确定性 Semantic Hash。

允许的可见内部节点类型固定为业务实现逻辑，而非源码结构：`input`、`preprocess`、`decision`、`processing`、`llm_call`、`tool_call`、`agent_call`、`state_read`、`state_write`、`validation`、`loop`、`retry`、`fallback`、`output`。

函数、类、文件只能出现在 Evidence 中，不能直接成为子画布逻辑节点。没有证据的分支、调用、因果或执行顺序不得由 AI 补造。

### 3.2 正式 Target 设计

Panorama Core 0.1/0.2 以向后兼容可选字段新增 `architecture.moduleLogicDesigns[]`。每个设计绑定：

- 稳定 Design ID、Module ID、Target/Historical Scope、名称与摘要；
- 逻辑节点、逻辑边、边界端口；
- Requirement、Decision、Risk、Acceptance/Gate 和 Reference；
- 外部模块交互必须绑定正式 `connectionId`；外部资源交互必须绑定已有 Resource 使用关系或明确标记未绑定候选。

阅读模式的 Current 不写入这个数组；该数组只承载经过 Proposal/Approval/Apply 的正式设计语义。首次修改 Schema 前必须先记录 Schema Finding，不能借 `extensions` 隐藏核心模型。

### 3.3 进度、风险与决策定位

为 WorkItem、Risk、Decision 增加可选 `relatedArchitectureRefs[]`，允许精确引用正式 Layer、Module、Connection、Target Module Logic、Logic Node、Logic Edge 和 Boundary Port，同时保留已有 `moduleIds/relatedModuleIds` 兼容字段。Core 不直接引用可失效的 Current Observation Node；Current 节点级定位保留在带 Observation Hash 的 Event/Explain 投影中。

- 工程 Event 已有通用 `subjectRefs`，无需改变 Envelope；投影器只在引用 ID 能被当前 Model/Observation 精确解析时高亮。
- 主画布聚合 Layer/Module 进度；子画布显示 Logic Node 级进度。
- 只读进度投影必须区分 `claimed/in_progress/implemented/verified/approved/deployed`；它不替换 WorkItem 现有状态枚举，也不得把事件、代码存在或 WorkItem 完成直接提升为验证、批准或部署事实。

### 3.4 Model/View/Explain/Studio

- Model IR 新增 `module_logic_node`、`boundary_port` Entity Kind，以及 `logic_flow`、`port_binding`、`resource_usage` Relation Kind；外部模块/资源继续复用正式实体身份。
- View IR 新增只允许作为嵌套子画布的 `module_logic` Profile 和必需的 `rootModuleId/parentViewBinding`；它不能成为第七个顶层并列 Tab，外部引用只投影紧凑 Node，不复制其内部逻辑。
- Explain Pack 新增绑定 Module Logic View 的整图、节点、边界交互、风险、决策和进度 Story。
- Studio Session 新增 `moduleLogicCanvases[]`；Current Observation 与 Target Candidate 分开保存，Semantic/Layout Hash 继续分离。

## 6. Definition of Done

只有以下条件全部成立，V0.8 才具备再次提交发布评审的资格：

1. 页面任一时刻只有一个 Canvas Runtime/World；阅读与编辑共享同一几何、相机和 Selection。
2. 架构主画布与模块内部逻辑子画布双向导航可用，外部引用不泄漏其他模块内部逻辑。
3. Current 内部逻辑全部绑定源码 Evidence 和 Source Hash；不支持或无法证明的内容明确为 Gap。
4. Target 内部逻辑可编排、可比较、可验证、可 Proposal，且从不覆盖 Current。
5. 数据流、Runtime、Sequence、Lifecycle、Evolution/Risk 不再是割裂页面，而是同一语义场景的镜片。
6. 讲解覆盖整图、节点、交互、风险、决策、进度和动态变化，并形成可读的完整逻辑链。
7. Layer/Module 中文主扫描层完整，技术名称与证据仍可追溯。
8. 三个代表项目、对抗 Fixture、全浏览器矩阵、旧版本回归和治理负向测试通过。
9. 新候选有独立 PVD ID、Artifact SHA-256、机器 Receipt 和人工视觉批准；旧 V0.8 候选不复用批准。

## 7. 本次批准不包含的动作

本计划不授权立即修改业务项目、不授权自动采纳 AI 归纳为正式 Current/Target，也不授权 Commit、Tag、Release、last-good Promotion 或代替用户执行人工视觉接受。每个 Schema/Renderer 候选仍按现有治理和验证合同推进。
