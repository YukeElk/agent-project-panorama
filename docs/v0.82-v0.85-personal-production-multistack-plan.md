# V0.82–V0.85 Personal Production & Multi-stack Plan

状态：Approved for implementation by user request on 2026-08-24; external release not yet approved

## 1. 目标与边界

V0.82–V0.85 只面向完整个人项目全景：单项目、本地单用户、Codex 运行终端、受信任业务仓库。
不把团队协作、RBAC、SSO、中央服务、组织级项目组合或远程多人编辑纳入发布门禁。

完成标准不是“识别到更多文件后缀”，而是让受支持语言和技术栈进入同一证据链：

```text
Repository Inventory
→ Language / Manifest / Framework / Infrastructure Adapter
→ Source Topology Observation
→ Source-to-Module Candidate
→ Model/View IR
→ 架构主画布 / 模块逻辑子画布 / 数据流 / 讲解
→ Continuous Observation / Verified Delivery
```

静态源码只产生 declared/derived candidate；不得把 import、route declaration、DI registration、ORM model、
container definition 或 workflow 声明冒充 observed runtime call、Sequence order、正式 Module 或已部署事实。

## 2. 支持等级

| Level | 能力 | 可宣称范围 |
| --- | --- | --- |
| L0 detected | 识别语言、Manifest、框架和基础设施信号 | 只可称 detected |
| L1 topology | 文件、包/namespace、静态依赖和声明式技术栈关系 | 可称 source topology supported |
| L2 architecture / module-logic candidate | 有证据的责任分组、接口/数据/资源边界，以及有界内部处理、分支、Loop、LLM/Tool、端口与跨模块引用 | 只读 derived Observation；正式 Module/Target 仍走评审与 Studio Proposal |
| L3 runtime observed | 受信 Event/Trace/Receipt 证明实际调用、顺序或运行状态 | 只陈述精确 Observation 时间边界内的运行事实 |

正式支持矩阵必须分别记录 detected/topology/moduleCandidate/moduleLogic，不允许用一个 Supported 布尔值掩盖能力差异。

## 3. 版本闭合

### V0.82 — Adapter Foundation & Personal Production Gate

- 冻结 Multistack Adapter Contract、支持等级、能力矩阵和确定性 Registry；
- 保留 Python AST，并深化 Python/JS/TS Manifest 与框架信号；
- Source Observation 增加可扩展语言、技术栈和 Adapter Capability 投影；
- GitHub CI 执行全部 Python/JavaScript 测试，并预留可复现 Browser Matrix 门禁；
- 发布审计自动核对 Tag/CI/安装态/last-good，不再以未回填清单作为当前事实。

### V0.83 — Mainstream Backend Languages

- Kotlin：package/import 与 Gradle/Kotlin Script Manifest；
- Go：package/import 与 go.mod；
- C#：namespace/using 与 SDK-style `.csproj`；
- Java/Kotlin/Go/C# Source-to-Module Candidate；
- 每种语言通过 resolved/external/unresolved、注释/字符串、越界和篡改负向测试。

### V0.84 — Cross-stack Architecture Signals

- Web/API：React、Next.js、Vue、Vite、Express、NestJS、FastAPI、Django、Flask、Spring Boot、ASP.NET Core、Gin/Fiber；
- Data/AI：ORM、SQL migration、Redis、vector/RAG/LLM/Agent/Tool 声明信号；
- Interface/Infra：OpenAPI、GraphQL、gRPC、Docker/Compose、Kubernetes、Terraform、CI workflow；
- 所有信号只进入 `stackProfile`/candidate，不从名称猜运行或部署状态。

### V0.85 — Secondary Languages, Monorepo & Release Review

- Rust、PHP、Ruby、Swift、Scala、C/C++ 的 bounded dependency adapter；
- Cargo、Composer、Gemfile、Swift Package、CMake 等 Manifest；
- 多语言 Monorepo 按 workspace/build boundary 生成候选，不按目录数量生成 Module；
- 对 Python、JS/TS、Java/Kotlin、Go、C# 和第二梯队固定项目运行 Capability Matrix；
- 完成全量测试、Schema meta-validation、determinism、privacy、CI、Browser Evidence 与安装烟测；
- 生成 V0.85 Release Audit。外部 Tag/Push/Release 仍需独立用户发布批准。

## 4. 生产验收指标

每个宣称 L1 的 Adapter 必须满足：

- Evidence Pin coverage = 100%；
- forbidden-claim avoidance = 1.00；
- 固定验证集 supported fact recall ≥ 0.90；
- 同输入、同 as-of 的 Observation/Receipt/Loss Hash 可重算；
- parse failure、动态加载、反射、生成代码和不支持语义显式进入 Gap/Loss；
- 不持久化源码正文、Prompt、模型输出、绝对路径或 Secret value；
- 无网络、无依赖安装、无项目写入、无项目代码执行。

L2 必须另行验证责任分组准确性、外部端口绑定、内部节点/边 Evidence、Currentness 和 stale 传播；L3 还必须
验证受信运行来源、Correlation、顺序和时间边界；
未达到指标的 Adapter 只能标为 preview/partial，不能阻止其他已支持栈形成 complete coverage。

## 5. 发布 Gate

V0.85 发布评审必须逐项给出 PASS/FAIL/NOT_APPLICABLE：

1. Schema/Contract；
2. Python 3.10/3.12 全量测试；
3. Node JavaScript 测试；
4. Exact Candidate Browser/Viewport/Console/Interaction Evidence；
5. 多语言 Capability Matrix；
6. Source/Module/Model/View/Explain Binding；
7. Continuous Observation stale/reconcile；
8. Privacy/Secret/Path/Capacity；
9. Verified Delivery/last-good recovery；
10. Skill quick validation 与隔离安装烟测。

任何 P0 Gate 失败只能得到 `Release Review: NO-GO`。人工“批准发布”可以绑定唯一冻结候选，不能覆盖机器失败或缺口。
