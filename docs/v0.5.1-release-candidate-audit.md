# Agent Project Panorama V0.5.1 本地发布候选审计

审计日期：2026-08-21

状态：**Internal Milestone Ready — Release Deferred；尚未 Commit/Tag/Release/安装，远程 Python 3.10/3.12 CI 待内部冻结验证**

分支：`agent/v0.5.1-event-head-policy-adapter`

基线：`55669d80a1e2d3dbe9d35de9c7be5e348b76d70b`（V0.5.0）

## 1. 范围结论

本候选只接入首个真实 Delegated Policy Operation：`event_head.recover`。没有接入
`engineering_event.record`、Continuous Observation、Verification Receipt、Studio、INIT、Renderer、View
IR、cat-sys Backfill、RAG/Eval/Dataset Export 或后训练。

已交付：

- 只读 Head State Inspector：`current/head_missing/head_behind/head_ahead/head_mismatch/head_invalid/
  chain_invalid/ambiguous/uninitialized`；
- 只允许 missing/精确 behind 的 Head Recovery，以及 Preview 的 State/Before/Tail CAS；
- 固定 Project-local Store、正式 Panorama Project/Schema/Revision/Data Hash 与精确 Policy Profile；
- 带 `stateHash` 的 `panorama-event-head-recovery-transaction.v0.1`；
- Preview/Execute/Resume/Validate CLI；
- Audit Event、Execution Receipt、Use Ledger 与 Adapter Transaction 端到端对账；
- SF-38、独立 Adapter 合同、README 与 SKILL 路由。

## 2. 审批与安全边界

- Inspect、Preview、Validate、current no-op 不需要人工审批，也不分配 Use；
- missing/behind 只有在已由人工精确批准并激活的 `event_head.recover` Policy 内才免逐次审批；
- Policy 创建、变更、续期、替换、撤销仍要求人工精确批准；
- ahead/mismatch/invalid/Fork/重复或不连续 Sequence、Hash/Schema/Project/Stream/Epoch 错配、Redaction
  歧义全部 fail closed；
- Adapter 不修改既有 Event、Panorama Core、Redaction/Epoch、业务源码或 Git；
- Store 由 Project Root 固定派生，拒绝路径逃逸和已检测到的符号链接；
- `engineering_event.record` 继续 No-Go，因为 Policy v0.1 尚未绑定 Event Type、Actor/Producer、Authority、
  Label Strength、Subject 和 Access Class。

## 3. 故障与幂等证据

本地测试覆盖：

- current 返回零 Use no-op；
- missing 与精确 behind 成功恢复；
- ahead/mismatch/invalid/chain tamper/redaction ambiguity 拒绝；
- Policy Scope 漂移、过期、撤销在事务/Use 前拒绝；
- post-prepared 与 post-allocation 重试复用原 Transaction/Use；
- post-effect/pre-Audit 重试不执行第二次恢复；
- Audit Event durable/Head 发布失败时只推进到精确 Audit Tail；
- Receipt durable/Ledger 发布失败只使用 Core `recover_pending()`；
- Core 已完成/Transaction finalize 失败时只对账 finalize；
- Transaction State Hash 篡改停止；
- CLI Preview/Execute/Validate 端到端通过。

成功/no-op 的 Receipt 绑定 Audit Event；failed Use 不伪造成功 Event。`outputHash` 绑定 Audit 前的恢复 Head，
`eventBinding` 绑定 Audit Event，`finalHead` 绑定 Audit 后 Stream Head。

## 5. 1,000 Event 容量证据

使用 1,000 条最小、Schema/Hash/Sequence/Previous Hash 均有效的 Event Chain，在本机 Python 3.12 +
`tracemalloc` 下记录：

| 项目 | 结果 |
| --- | ---: |
| Event 生成 | 2.390 s |
| missing Head 恢复 | 29.589 s |
| 恢复后完整复验 | 6.466 s |
| 峰值 Python 跟踪内存 | 11.078 MiB |

这是一次容量基线，不是 SLO。恢复阶段仍对每个 Event 执行完整 Schema/Hash/Chain 校验；在不降低验证强度、
不引入陈旧 Schema Cache 的前提下，可以在后续版本单独优化扫描成本。

## 6. 已知限制与 Release Decision

- 本地只验证 Python 3.12；GitHub Actions Python 3.10/3.12 尚未运行当前未提交分支；
- Windows 符号链接拒绝路径有实现与静态测试，需 Linux CI 实际通过；
- Operation Transaction 是 `event_head.recover` 专用合同，不是通用 Saga/Agent Runtime；
- Redaction Epoch 仍分类为 ambiguous，不自动解释或修复；
- 1,000 Event 恢复扫描尚未声明性能 SLO；
- 尚未 Commit、Push、Tag、创建 Release 或更新已安装 Skill。

因此技术结论仍是本地候选完整，但产品发布决策调整为 **Internal Milestone Ready — Release Deferred**。
本切片应形成开发分支内部提交并在最终 Commit 上运行 Python 3.10/3.12 CI，以便为后续工作提供稳定基线；
不创建公开 Tag/Release，不更新已安装 Skill，也不单独宣传为用户可用版本。
