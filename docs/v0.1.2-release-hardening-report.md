## 2. 行为变化

### P0-INIT

- Before：当 `--output` 已存在时，INIT 在校验后直接替换，调用方无法区分首次创建与覆盖。
- After：默认返回非零且保持原文件不变；只有显式 `--overwrite-existing` 才会在全部校验通过后创建同目录时间戳备份并原子替换。无论是否允许覆盖，模板与输出为同一文件或同一文件实体时都拒绝。
- Why：避免静默覆盖用户项目，同时保留可恢复副本和暂存后提交语义。

### P1-Review Audit

- Before：默认 Proposal 的 `reviewDraft.status`、`reviewedBy`、`reviewedAt` 在用户批准前已被写成 approved/user/提案时间。
- After：所有 Proposal Review Draft 被规范化为 pending、空 `reviewedBy`、null `reviewedAt`；用户只修改 Approval。Apply 校验 Proposal Hash 后，从 Approval 的 `status`、`approvedBy`、`approvedAt` 物化最终 Review，原 Proposal 语义与 Hash 不变。
- Why：最终审计记录反映真实批准主体与时间，不把提案生成行为伪装成人工批准。

### P1-Affected Entity

- Before：把 Operations 序列化后用现有 ID 做子字符串搜索，无法发现新实体，也可能把自由文本中的 ID 误判为受影响对象。
- After：比较 current/preview 注册表中的实体对象，并用 Pointer 路径与结构化 value 补充主实体识别；覆盖 add/remove/replace、完整候选 diff、Module 与 Connection。
- Why：受影响实体来自结构变化，不来自显示文本碰撞。

### P1-Finding Entity Mapping

- Before：Finding 只有级别、严重度、代码、消息和路径；Attention 的 `relatedEntities` 固定为空。
- After：`ValidationIssue`、JSON 输出和 Report 均包含 `relatedEntities`。Architecture、Review、Verification、Deployment、Transition、Resource、Git Secret、Stage Entry/Exit 等规则绑定相关工程对象；Attention 深拷贝原 Finding 的实体列表。
- Why：重大风险能够稳定指回具体需求、模块、连接、发布、部署、资源、阶段或验收对象。
